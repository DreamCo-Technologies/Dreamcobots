Study a dataset with Buddy

Users can inspect public metadata and test a split before choosing whether to download any files. The preflight checks up to 100 returned rows for schema problems, missing values, duplicates, mixed types, likely emails/phone numbers/SSNs/payment cards/credentials, active HTML/script markers, and prompt-injection phrases. It flags sensitive-looking field names, unsupported formats, and dataset scripts, and removes sample values from its saved report. Pattern scans can miss issues or flag ordinary text. The Dataset Viewer preview is not pinned to the selected commit, so users must review it against that exact revision. A successful preview cannot prove safety, rights, privacy, or quality.

python3 tools/buddy_discover_hf_dataset.py OWNER/DATASET main resolves the selected revision and lists supported files without downloading them.

python3 tools/buddy_discover_hf_dataset.py OWNER/DATASET main --preview --config CONFIG --split SPLIT fetches split metadata and a redacted sample schema before download. Script files are flagged and never run. Users still review the publisher, dataset card, license and terms, provenance, selected files, hash, and intended use; download rights and model-training consent are separate choices.

python3 tools/buddy_study_dataset.py ./dataset.csv --owner-id YOUR_USER_ID --buddy-id YOUR_BUDDY_ID --source-url https://huggingface.co/datasets/OWNER/NAME --source-family hugging_face --license LICENSE_ID --rights-reviewed --terms-checked --private-study

Use --owner-created --consent-receipt RECEIPT_ID for a dataset you created. Private study, private training, shared-fleet training, and publication each require separate permissions. User-created data remains user-owned; Buddy's access is a scoped permission.

Review models, chatbots, and open-source GitHub components

Use the provider-neutral resource preflight for hosted/local models, chatbots, agents, MCP servers, and tools. It records evidence and missing checks without connecting credentials. A selected GitHub folder can be reviewed at a pinned commit before users choose whether to copy it. Copying requires authorization, a reviewed identified license, preserved notices, and at least two DreamCo customizations.

python3 tools/buddy_resource_preflight.py ai MODEL_ID ai_model PROVIDER https://provider.example/model --revision REVISION --license LICENSE

python3 tools/buddy_resource_preflight.py github https://github.com/OWNER/REPOSITORY --select src/agent --output review.json

python3 tools/buddy_resource_preflight.py clone-selected review.json ./my-dreamco-module --confirm-authorization --confirm-license-review --customize workflow --customize privacy --differentiator "Describe an original DreamCo behavior that serves my users."

DreamCo Code Workbench

DreamCo’s own code analysis system is available for local source repositories. It records repository structure, language and dependency manifests, entry points, route hints, tests, and documentation as file-and-line evidence. It does not execute target code, fetch the repository, or copy source into its report.

Run python3 tools/dreamco_code_workbench.py /path/to/authorized/repository --owner-authorized --customize workflow --customize privacy --differentiator "Describe the original DreamCo product direction here" from the Dreamcobots checkout. Choose at least two customizations and write an original differentiator.

For model, website, app, game, film/media, and API targets, prepare a scoped plan with python3 tools/dreamco_investigation_plan.py --help. These profiles specify evidence and test methods; a separate isolated adapter is required before any live connection or execution.
