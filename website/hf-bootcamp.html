Buddy boot camp

Ten data packages. DreamCo wrote the lesson. Only the official Hub sync is wired.

1. Hugging Face Sync

Copies a GitHub repo into a Space and adds the Space header so the Hub page can open.

We keep the Space header only inside huggingface/dreamco-router/README.md. GitHub pages stay plain.

Source

2. Sync GitHub to Hugging Face Hub

Official action. Uses the hf tool to upload a folder as a Space, model, or dataset.

This is the one workflow we installed. It uploads only the beginner-router folder when you run it.

Source

3. Sync With Hugging Face Space

Keeps a separate YAML file and sticks it on the README only on the Space.

Same idea, already done by hand in the router README. We do not run this second uploader.

Source

4. Sync With Hugging Face Hub

Older community uploader for model, dataset, or Space.

Studied. Replaced by the official hub-sync action so we do not keep two uploaders.

Source

5. Hugging Push

A push of the current repo into a Space repo.

We do not push the whole DreamCo repo. Notes and plans stay on GitHub.

Source

6. Hugging Repo

Same job as Hugging Push: mirror repo files to a Space.

Treated as a duplicate lesson. One uploader is enough.

Source

7. Deploy to Spaces, models, or datasets

One action can target a Space, a model repo, or a dataset repo.

The workflow asks which of the three you want each time you run it.

Source

8. HF Model Inspector

Reads a public model card and writes a short report about size and use.

Our report is the model card plus the 12-prompt check. We do not inspect someone else's weights.

Source

9. MLX Model Doctor

Checks a model folder before load: config, tokenizer, shards, memory.

We have no MLX weights. The lesson is: do not load a model until a check passes.

Source

10. Auto release with an AI description

Writes a release note by sending the change list to a model.

Boot camp does not send the repo to an outside model to write release notes.
