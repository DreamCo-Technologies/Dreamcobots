Quick start: Open Buddy Bot and type your first request. Buddy routes it to the right specialist bot automatically — no configuration required.

Quick Start

DreamCo Empire OS runs entirely in your browser with no installation required. For advanced features and API integrations, follow the steps below.

1. Open Buddy

Navigate to buddy.html (or the deployed GitHub Pages URL). Buddy is your single command interface for all 1,051 bots.

2. Choose a Model Tier

Buddy operates in two tiers out of the box:

  • Free tier — Uses Buddy's built-in routing and prompt engineering. No API key needed.
  • Premium tier — Connects to OpenAI GPT-4.1-mini (or your chosen model). Requires your own API key stored locally.

3. Activate API Integrations

For live data, payments, and third-party services, add your keys in Data & Memory Controls. Keys are stored only in your browser's local storage — never sent to our servers.

Buddy Bot Architecture

Buddy is the central command interface for the entire DreamCo fleet. Every user request passes through Buddy's governed routing layer before reaching any specialist bot.

ArchitectureRequest flow
User Input ↓ Buddy Router (config/buddy-model-router.json) ↓ Autonomy Gate (checks mode: guided / scheduled / governed) ↓ Specialist Bot (one of 1,051 in App_bots/) ↓ Capability Execution (server/fleet-runtime.ts) ↓ Response → Buddy → User

Commands & Routing

Buddy understands natural language. Common patterns:

  • Analyze my real estate deal at [address] → routes to DreamRealty division
  • Write a sales email for [product] → routes to DreamContent or DreamSales
  • Check my portfolio performance → routes to DreamFinance or DreamEntFinance
  • Debug my Python script → routes to DreamCodeLab
  • Run my weekly report → routes to DreamOps with Scheduled autonomy

Model Selection

Buddy uses a Mixture-of-Experts (MOE) routing strategy. The config/buddy-model-router.json defines which model handles which task type:

Task TypeDefault ModelNotes
General routingGPT-4.1-miniFast, cost-efficient

Autonomy Modes

DreamCo Empire OS supports three autonomy modes that control how independently bots operate. You can change the mode at any time from Autonomy Settings.

🎮 Guided Mode

Every bot action requires your explicit approval before execution. Buddy presents a proposed action and waits for your Approve or Reject response.

Best for: High-stakes decisions, learning the system, or any scenario where you want full transparency. Available on all plans including Free.

📅 Scheduled Mode

Bots execute at defined times — daily, weekly, or monthly. You configure the schedule; Buddy ensures tasks run on time and reports results.

Best for: Recurring reports, automated digests, and time-sensitive workflows. Available on Pro, Enterprise, and Elite.

🚀 Governed Autonomy

Bots operate 24/7 within your defined safety boundaries. All actions still pass through Buddy's governed safety layer — external payments and destructive actions require an extra confirmation even in this mode.

Note: Governed Autonomy requires a connected payment method and is available on Enterprise and Elite plans only.

REST API Reference

The DreamCo REST API provides programmatic access to Buddy, the bot fleet, and task management. All endpoints require a valid Authorization: ******;token> header.

Base URL: https://your-deployment-url.run.app/api/v1 — or http://localhost:5000/api/v1 locally.

Bots API

GET/bots
List all 1,051 bot profiles with division, capabilities, and tier information.
GET/bots/:id
Get detailed profile for a single bot including business blueprint and sandbox contract.
GET/bots/divisions
List all 45 divisions with bot counts and API candidate counts.
POST/bots/:id/run
Execute a bot capability. Respects current autonomy mode.
ExampleGET /bots/1
{ "id": 1, "name": "DreamBot", "division": "CommandCore", "tier": "free", "capabilities": ["task-routing", "system-coordination"], "autonomy_support": ["guided", "scheduled", "governed"], "buddy_route": "dreambot" }

Tasks API

GET/tasks
List all tasks (pending, running, completed, failed).
POST/tasks
Create a new task. Body: {"bot_id", "input", "autonomy_mode"}.
GET/tasks/:id
Get task status and results.
DELETE/tasks/:id
Cancel a pending or running task.

Schedule API

GET/schedules
List all configured scheduled tasks.
POST/schedules
Create a new schedule. Body: {"bot_id", "cron", "input", "label"}.
DELETE/schedules/:id
Remove a scheduled task.

Deployment: Cloud Run

Google Cloud Run is the recommended production deployment target for the DreamCo backend API.

bashCloud Run deployment
# Authenticate and set project gcloud auth login gcloud config set project YOUR_PROJECT_ID # Build and deploy gcloud run deploy dreamco-api \ --source . \ --region us-central1 \ --allow-unauthenticated \ --set-env-vars NODE_ENV=production,DATABASE_URL=$DATABASE_URL

The cloudbuild.yaml in the repository root configures automatic builds on push to main.

Deployment: App Engine

For App Engine Standard with auto-scaling:

bashApp Engine deployment
# Deploy using app.yaml configuration gcloud app deploy app.yaml --project YOUR_PROJECT_ID

The app.yaml in the repository root defines the Node.js 22 runtime, instance class, and environment variables.

45 Divisions

Every bot belongs to exactly one division. Divisions group bots by domain expertise and allow Buddy to route requests efficiently.

Browse the full interactive catalog at Bot Fleet →

Bot Profiles

Each bot profile in App_bots/<Division>.json declares:

  • name — Unique identifier and display name
  • capabilities — List of declared capability slots
  • tier — Minimum plan required (free / pro / enterprise / elite)
  • autonomy_support — Which autonomy modes this bot participates in
  • sandbox_blueprint — Contract tests proving each capability
  • business_blueprint — Revenue model and ROI projections
  • governed_lead_system — CRM and lead-capture configuration
  • buddy_route — The Buddy routing keyword for this bot

Capabilities

The full fleet declares 8,408 capability slots. A capability is a discrete, testable action a bot can perform — for example analyze-credit-report, generate-marketing-copy, or run-backtest.

Inspect all capabilities per bot from the bot catalog, or query GET /bots/:id via the API.
