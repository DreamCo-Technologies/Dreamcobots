2. Goal → Action → Evidence → Learning

Goal→Ontology traversal→Context ranking→Debate→Plan→Model + tools→Action→Evidence→Benchmark→Mastery / Gap→Learn

🧬 Operational Ontology

DreamCo uses a hybrid operational ontology: disciplined upper concepts, enterprise architecture patterns, semantic interoperability, property-graph traversal, provenance, temporal state, agent reasoning, software relationships and AI/MLOps objects.

Core relationships include depends_on, supports_goal, executes, requires, produces, tested_by, uses_model, uses_weight, governed_by and recovers_from.

🔄 Ontology Evolution

New ontology patterns follow: Discover → Extract Hint → Map → Score → Detect Conflicts → Prototype → Benchmark → Sandbox → Observe → Approve → Adopt → Monitor → Deprecate.

The adoption scorecard is designed to prevent semantic bloat and requires measurable value before runtime promotion.

🧠 Context Fabric

Buddy ranks goal alignment, authority, freshness, evidence quality, task dependency and reliability. Instructions, preferences, notes, generated content and verified evidence remain distinct.

Large contexts are compressed while preserving source pointers. Secrets are excluded from general indexes.

⚡ Efficiency

Hot paths include goal→capabilities, capability→bots, capability→benchmarks, bot→tools, tool→MCP, repository→workflows, incident→evidence and failure→fix.

Caching, typed indexes, bounded traversal and parallel retrieval are preferred over dumping the repository into model context.

3. Model Weight Strategy

Model sources

Hosted models · local weights · approved open weights · specialist models · embeddings · rerankers · coding · vision · speech.

Routing

Choose by task fit, benchmark score, latency, memory, hardware, cost, privacy, reliability and license constraints. Use the smallest sufficient model and escalate when evidence requires it.

Weight lifecycle

Discover → license check → download → integrity verify → sandbox → benchmark → security review → approve → deploy → monitor → retire.

4. Division Efficiency Program

Inventory→Benchmark→Find duplicates→Find bottlenecks→Consolidate→Shared services→Canary→Monitor→Promote/Rollback

Measured signals include goal completion, benchmark pass rate, user success, duplicate capability rate, tool failure, recovery, latency, compute/model cost, incidents, automation coverage, human escalation and evidence completeness.

5. Benchmark & User Testing

SANDBOX / REPOSITORY

The repository has established sandbox/certification infrastructure. Current evidence records 1,051 bot profiles and 8,408 capability contracts in the repository-controlled certification baseline.

REAL USER TESTING

Priority flows: Buddy Actions, bot control, dashboards, professional debugging, Buddy Bootcamp, benchmark center, memory/context and debate team.

LIVE PROVIDER

MCP, GitHub, external APIs, authenticated providers, deployment, observability and other external integrations require their own live evidence.

PRODUCTION

Production promotion requires deployment evidence, monitoring and governed rollback. Sandbox success never silently becomes production success.

6. Professional Debugging / Preventive Engineering

🔎 Detect

Health checks, CI, tests, observability, dependency drift, ontology quality gates and regression signals.

🧩 Diagnose

Connect symptoms to traces, commits, dependencies, capabilities, incidents and prior evidence.

🛠️ Repair

Generate the smallest reusable fix, prefer shared infrastructure, sandbox it and preserve rollback.

✅ Prove

Run targeted tests, benchmarks and regression checks, then record evidence and update mastery.

7. Debate Team

For consequential architecture and system-building decisions, Buddy can structure competing proposals around Task → Purpose → Data → Constraints → Alternatives → Evidence → Risks → Decision → Acceptance Tests. Dissent remains visible instead of being collapsed into a single unsupported answer.
