# Edu Career Pathways: majors to O*NET study plans

Maps bachelor's majors (2020 CIP codes) to O*NET-SOC occupations using the official O*NET CIP crosswalk, then writes one study plan per major (1,044 majors in two tiers, see Coverage): linked occupations with O*NET 31.0 Job Zones, the highest-importance O*NET knowledge areas and Essential Skills, 1 to 3 Job Zone-based entry-level targets, a 4-year outline, typical next steps, and 6 practice tasks with rubrics. The outline, next steps, and practice tasks are DreamCo-derived guidance, not O*NET data.

Fetch pinned sources: `python fetch_sources.py` (verifies sha256). Rebuild: `python build.py` (needs pandas, openpyxl; set `DREAMCO_GATE_TOOL` to `tools/license_provenance_gate.py` if it is not found automatically). Test: `pytest tests` (needs jsonschema for schema checks).

Inputs:
- `raw/` pinned official files (hashes in `raw/SOURCES.md`; raw data files are not committed).
- `authored/` checked-in DreamCo-authored sources that build.py reads, so builds are reproducible:
  - `practice_tasks_authored.json`: 162 practice tasks for the 27 authored majors. Each cites an O*NET 31.0 Task ID and O*NET-SOC code and has an original-wording paraphrase of the task's intent, an occupation-specific scenario prompt, a 3-criterion rubric for that scenario, and a reference answer outline.
  - `outline_topics.json`: per-major course-topic and practice mappings, keyed by CIP and O*NET element, for every element each authored outline uses.
  - `target_overrides.json`: manual entry-target overrides with reasons, plus review notes for majors kept as computed.
  - `coverage_rules.json`: which CIP codes get a plan (inclusion rule, excluded series, prefixes and title patterns, each with a reason).
  - `release_changes.json`: what changed versus the previous release (8cc1ce1), including each replaced practice-task citation with its reason; read by `regression.py`.
  - Authorship of all five: DreamCo-original, authored by Grok-Edu-Career-Pathways (AI), not human-reviewed.

Outputs:
- `data/major_to_onet.csv`, `data/majors_selected.json` (incl. tier, Job Zones, entry targets and target review), `data/practice_tasks.json`, `data/coverage.csv` (every CIP code in the crosswalk with included/excluded and the reason).
- `study_plans/<cip>_<slug>.md` (human layer) and sidecar folder `study_plans/<cip>_<slug>/` with `plan.json` (machine layer), `provenance.json`, `asset.json`, `candidate.json`, and `license_gate.json` (output of the DreamCo license/provenance gate).
- `data/dreamco_knowledge/evidence/regression/<asset_id>/<YYYYMMDD>-<NN>.json` (evidence record) and `.results.json` (item-level results), written by `regression.py`.
- Sources and hashes: `raw/SOURCES.md`. Test schemas snapshot: `tests/schemas/` (used when the live DreamCo schemas are not present).
- Data dictionary: `docs/DATA_DICTIONARY.md` (machine-readable `docs/data_dictionary.json`, generated by `docs/make_data_dictionary.py`) documents every output file and field; a test checks it against the outputs.
- Blind holdout grading kit: `evidence/holdout_kit/` (see Method notes). `make_holdout_kit.py` draws it; `score_holdout.py` scores a filled-in sheet.

Coverage and tiers:
- **authored** (27 majors, `build.MAJORS`): practice tasks, outline course topics and target review written for each major (see `authored/`).
- **generated** (1,017 majors): every other 6-digit CIP 2020 code in the crosswalk with at least one linked O*NET 31.0 occupation in Job Zone 4 or 5, after excluding non-bachelor programs (`authored/coverage_rules.json`). Excluded: CIP series 12, 28, 29, 32-37, 46-49, 53, 60, 61; 51.39 practical nursing; graduate/first-professional programs (law J.D. and LL.M., medicine, dentistry, optometry, chiropractic, veterinary, pharmacy apart from the authored 51.2001, physician assistant, physical and occupational therapy, audiology, divinity, graduate medical sciences); titles containing Technician, Assistant/Assisting, Aide, Apprentice or Police Science; and 133 codes whose linked occupations are all Manager, Chief, Postsecondary-faculty or All Other titles (no entry target can be named). 771 of the 1,948 crosswalk codes are excluded; `data/coverage.csv` lists each one with its reason.
- Generated plans say "Tier: **generated**" at the top, and `plan.json` and `majors_selected.json` carry `"tier": "generated"`. Their outline lists O*NET element names only, their entry targets are the unreviewed rule output (`entry_target_review.type = rule_only_not_reviewed`), and their 6 practice exercises use one DreamCo template around the cited O*NET task statement. The statement is quoted verbatim on an attributed quote line (USDOL/ETA, CC BY 4.0) and in `onet_task_statement`; it is O*NET content, not DreamCo-owned. Authored plans quote no O*NET task text. Generated plans have no regression evidence because they did not exist in the previous release.
- BLS Occupational Outlook Handbook data (typical entry education, median pay, outlook) is **not** included. On 2026-10-02 every official BLS endpoint tried from this box returned HTTP 403 "Access Denied": www.bls.gov/emp/ind-occ-matrix/occupation.xlsx, the occupational projections table page, www.bls.gov/ooh/, the OOH XML compilation, and download.bls.gov/pub/time.series/ep/ and /oe/. The fetch tool timed out on the same page. api.bls.gov responded but refused the request (keyless daily threshold) and does not carry the OOH fields anyway. No BLS figures were copied from secondary sources, because they could not be pinned and hashed from the official file.

Method notes:
- Entry targets: a rule first picks linked occupations in O*NET Job Zone 4 (typical bachelor's level), excluding titles containing Manager, Chief, Postsecondary, or All Other (and Supervisor, Director, or Treasurers and Controllers unless nothing else is linked), base `.00` codes first, ranked by correlation with the eligible occupations' average knowledge profile; fallback Job Zone 3, then 5, then 1-2. Every authored major's result was then reviewed for plausibility: 11 majors have a documented override in `authored/target_overrides.json` (for example, Computer Science now targets Software Developers, Software QA Analysts and Information Security Analysts instead of Database Architects), and the other 16 have a review note. Pharmacy uses Job Zone 5 (Pharm.D.), and Criminal Justice uses a Job Zone 3 supervisor title with a caveat, because its only crosswalk links are supervisors, faculty, and an All Other code.
- Practice tasks reference an O*NET 31.0 Task ID and O*NET-SOC code. O*NET task text is not reproduced: tests check that no run of 5 or more words from any O*NET 31.0 task statement, Job Zone reference text, or occupation description appears in the authored fields or in the plan files (occupation titles excepted).
- Typical next steps cite O*NET Job Zone numbers only; Job Zone names and descriptions are not quoted.
- Knowledge and skill weighting (v4): the outline uses entry-weighted means of O*NET importance. Entry targets weigh 2. Other linked occupations in Job Zone 4 or 5 (or the targets' own Job Zone) weigh 1. Manager, Chief, Postsecondary-faculty, All Other, Supervisor, Director and Treasurers and Controllers titles, and non-target occupations in other Job Zones, weigh 0 (`build.WEIGHTING_METHOD`; the weights are in `plan.json` `knowledge_weighting`). Plans also show the unweighted mean over all linked occupations for comparison (`top_knowledge`, `top_skills`).
- Outline placement and skipped elements: English Language goes to Year 1 general education. Year 2 takes the first 3 core weighted elements and Year 3 the next ones by entry-target importance. Cross-cutting workplace knowledge (Customer and Personal Service, Administration and Management, Education and Training, Personnel and Human Resources, Administrative, Clerical) is skipped. There are two exceptions: it is core for the series where it is the subject (business 52, education 13, public administration 44: `build.CORE_BY_SERIES`), and an authored major's `authored/outline_topics.json` can keep it with a reason (`core_keep`). Elements that rank below the six knowledge course slots are skipped for capacity. Every plan lists the top elements it skips, with the reason, under the outline and in `plan.json` `outline_elements.skipped_knowledge`. For example, CS now covers Design and Telecommunications, and states why it skips Administration and Management.
- Licensing (v4): every item in `data/practice_tasks.json` carries its own `license` and `ownership_class`. Authored items are DreamCo-original (synthetic_generated_by_dreamco) and only reference O*NET identifiers. Generated items quote an O*NET task statement, so they are third-party CC BY 4.0 content (open_license_with_conditions), with license URL, attribution, a modification notice and the trademark notice. Their DreamCo template layer is listed separately. The file-level label says licensing is per item; the earlier note is kept. Each `plan.json` has a `license` block with attribution, required notices and per-field components. All plan-text notices are unchanged. DreamCo commercial terms for its own layer are not set (owner decision).
- Generated-tier plausibility checks (v4, automatic, `plan.json` `quality_flags` and a "Quality flags" section near the top of each generated plan):
  - Practice tasks skip O*NET task statements that match a supervisory or managerial pattern (`build.SUPERVISORY_RULE`: supervise, provide supervision, direct and coordinate, direct the work of, manage staff, oversee staff, hire, subordinates, assign work to, evaluate the performance of, and train and supervise; "under supervision" is not counted). A plan keeps such a task only if fewer than 6 others exist, and flags it (none in this release).
  - A target is flagged `low_title_overlap` when its title shares no word stem with the CIP title (`build.OVERLAP_RULE`: lower-cased words, stopwords removed, simple suffix stripping, a match if two stems are equal or a stem of 5+ letters contains the other). Severity is high if the occupation description also shares no stem with the CIP title, and medium otherwise. The heuristic is crude: it misses synonyms and flags some sound targets. It marks plans for review and does not change them.
  - Also flagged: targets outside Job Zone 4, and fallback target rules.
  - Authored plans record supervisory citations as informational only, because their scenarios were written for them.
- created_at in asset.json, plan.json, practice_tasks.json and the holdout kit is a full ISO 8601 timestamp with offset. Builds use a fixed release timestamp (`DREAMCO_BUILD_TIMESTAMP`, default 2026-10-02T18:30:00-05:00) so rebuilds are reproducible.
- Evidence ids `<kind>:<asset_id>:<run>` resolve to `<evidence_root>/<kind>/<asset_id>/<run>.json`. `asset.json` names `evidence_root` = `study_packs/career_pathways/data/dreamco_knowledge/evidence` (repo-relative). Files stay where they are.
- Blind holdout kit (`evidence/holdout_kit/`), for the owner as the only available human grader. It has 12 items drawn with seed 20261002 from the 162 authored tasks, none of which were ever used for tuning. Each item has the scenario prompt, a candidate answer and the rubric. Six candidates are the authored reference outlines. Six are deliberately weakened versions, each with one criterion's content removed or made vague, shuffled into H01-H12. The grader fills in `grading_sheet.csv` (0-2 per criterion, factually_correct, comments) following `README.md` there. `_key.json` (sealed, not for the grader) holds the expected scores and accepted bands, and hashes of each source item and candidate. `python score_holdout.py --sheet evidence/holdout_kit/grading_sheet.csv --write` checks the sheet and the item hashes. It then writes `holdout:<asset_id>:<run>` records (human_evaluation, original_evaluation) with results files per asset, scoring the fraction of criterion scores inside the accepted bands (threshold 0.8). No grades have been entered and no holdout evidence exists.
- Regression evidence: `python regression.py --baseline-ref 8cc1ce1 --repo <git clone of Dreamcobots>` compares each plan in this build with the previous release, item by item. It checks linked occupation codes (title and Job Zone), knowledge and skill importance values and ranks, entry targets (presence and order), practice-task citations (practice id, O*NET-SOC code, task ID), that each citation is a real task of a linked occupation, license-gate checks (a check that passed must still pass), and O*NET text leakage in the plan (zero 5-word runs). Every difference must be explained by `authored/target_overrides.json` or `authored/release_changes.json`. Score = fraction of items that are preserved, improved, or changed with a reason; threshold 1.0, and any leakage fails the record. The record follows `config/evidence_provenance_schema.json` (source_type dreamco_experiment, transformation original_evaluation, source_reference = the asset's integrity_hash, integrity_hash = sha256 of the results file). build.py links a record into `asset.json` `validation_evidence_ids.regression` only if its source_reference matches the current plan hash, its hash matches the results file, and it passed. Results files are deterministic: no run timestamp, and the gate file is hashed as canonical JSON without `evaluated_at`. The `synthesis_asset_record` check is not compared, because it depends on the linkage itself. The release order is build, regression, build (links the records and reruns the gate), then regression again as the last step, so `current.files` in every results file matches the files on disk. A rerun on an unchanged build reproduces each results file byte for byte. Tests verify every evidence record's integrity_hash against its results file, and the results' file hashes against disk. A test checks that the comparator flags dropped links, unexplained targets, changed scores, swapped citations, gate regressions and leaked text.
