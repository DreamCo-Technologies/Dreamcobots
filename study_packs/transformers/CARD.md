# pack.transformers-core — Transformers core study pack

Purpose: working literacy in the four Transformers APIs every DreamCo open-model route touches:
`pipeline()`, the `Auto*` classes, `generate()`, and chat templates. This is courseware plus drills,
not training. Aligned with `docs/HUGGINGFACE_MASTERY_PLAN.md` (Phase 1 hub literacy, pack folder
contract). No file named `HUGGINGFACE_MASTERY_TRACK` exists in the repo; the plan is the track.

- capability_ids: `hf-transformers-pipeline`, `hf-transformers-auto`, `hf-transformers-generate`, `hf-transformers-chat-template`
- license: every pinned model has Hub license metadata (see `sources.json`); unlicensed repos are rejected
- revision pins: exact commit SHAs, passed as `revision=` everywhere
- weights: safetensors only, `trust_remote_code=False`, never committed to git
- automatic weight download in default CI: no (the unittest only checks the contract unless `TRANSFORMERS_CORE_DRILLS=1`)
- train_allowed: false
- teacher: `xai/grok-best-available` for critique of drill write-ups only
- privacy: no client data; all prompts are synthetic

## Layout

| Path | What it is |
| --- | --- |
| `sources.json` | Pinned model (repo, SHA, license) and rejected candidates |
| `evals.json` | Drill ids, checks, pass floor (1.0) |
| `drills/README.md` | Concept notes per module |
| `drills/run_drills.py` | Runnable drills with asserts; writes a run log to `evidence/` |
| `evidence/` | Real run logs (failures kept, not deleted) |
| `recipes/` | Empty on purpose; training is out of scope |

## Evidence so far (2026-09-28, CPU, Python 3.13.5, torch 2.14.0+cpu, transformers 5.17.0)

- `evidence/run_20260928T175119.json`: 3/4. `tc.generate.controls` failed because two greedy
  `generate()` calls diverged after 11 new tokens with multi-threaded CPU matmuls.
- `evidence/run_20260928T175252.json`: 4/4 after `torch.set_num_threads(1)`.

Lesson kept in the pack: `do_sample=False` is deterministic in math, not always in floating point.
Near-tie logits plus a thread-dependent reduction order can flip an argmax. Pin threads (or use
`torch.use_deterministic_algorithms`) before comparing greedy outputs byte for byte.

Not registered in `study_packs/index.json` because that index is regenerated by
`tools/build_hf_capability_packs.py` for the six capability packs only.
