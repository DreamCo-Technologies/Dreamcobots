# DreamCo-owned Bootcamp data and course catalog

## Purpose

This is DreamCo's canonical index for learning resources, existing repository datasets, original DreamCo lessons, generated task examples, benchmark tasks, and training-ready assets. It unifies the repository's knowledge without pretending that every linked external resource has been downloaded, studied, licensed for training, or transferred to DreamCo.

## The ownership distinction

Every record must be classified as one of:
- `dreamco_owned`: original DreamCo-created content with recorded authoring provenance.
- `dreamco_synthetic`: generated by DreamCo, with generator/version/inputs recorded and quality-reviewed.
- `licensed_for_training`: third-party data with a verified license and documented training scope.
- `reference_only`: a source pointer or documentation reference; not training data.
- `restricted` / `unknown`: blocked from training and redistribution pending review.

A resource being public, free to read, listed in GitHub, or available on Hugging Face does not by itself grant training or redistribution rights. Preserve source attribution, license conditions, version pins, and transformations. Never relabel third-party material as DreamCo-owned.

## Repository sources unified by the catalog builder

The builder indexes these existing sources rather than duplicating their contents:
- `website/data/free-datasets.json` — dataset discovery inventory; its own policy says files are not hosted or studied by this listing.
- `website/data/open-platforms.json` — tools and learning-platform references.
- `buddy/bootcamp/learning_source_catalog.yaml` and `buddy/bootcamp/resource_registry.yaml` — course/resource and model-training resource registries.
- `benchmarks/study_courses/course_catalog.json` — existing course catalog.
- `study_packs/*/index.json` and `study_packs/*/sources.json` — authored study packs and pinned sources.
- `config/buddy_benchmark_dataset_factory.json` and `config/buddy-training-data-provenance-policy.json` — dataset creation and rights controls.
- `config/onet-priority-curriculum.json` and `config/onet-sandbox-dataset-spec.json` — occupational capability and task mapping.
- `data/dreamco_knowledge/packages/*/*/manifest.json` — versioned data packages with field-level ownership/license manifests.
- `eval/edu_benchmark`, `eval/edu_mastery_scorecards`, and `benchmarks` — benchmark and mastery evidence.

The generated catalog records counts and references, not the content of every external source. It deliberately reports source inventory separately from files actually ingested and approved.

## DreamCo's own training-data perspective

DreamCo's differentiator is its own task ontology, capability graph, lesson sequence, examples, rubrics, synthetic variants, tool-use traces, failure/recovery cases, and verified outcomes. The perspective should synthesize:
1. What the source teaches (at the level of allowed concepts and metadata).
2. Which user outcome and occupational task it supports.
3. What skill and prerequisite it requires.
4. What a good result looks like.
5. How to practice safely.
6. How to test transfer on a newly generated task.
7. What failure modes and recovery strategies matter.
8. What evidence justifies mastery.

Do not copy whole course lessons, answer keys, proprietary datasets, or restricted benchmark items. Create original explanations and examples. Keep source pointers and attribution alongside the derived lesson.

## Record lifecycle

`discovered → rights_reviewed → metadata_ingested → lesson_authored → task_generated → quality_checked → train_eligible → benchmarked → approved`

A record can remain useful as reference-only. A source may not advance just because its URL resolves.

## Train/validation/test separation

- Train: authorized learning examples and synthetic practice records.
- Validation: development and model-selection examples.
- Test/holdout: sealed tasks not used for prompt tuning, fine-tuning, retrieval optimization, or lesson generation.
- Transfer: fresh tasks from different formats, contexts, and domains.
- Regression: previous failures and mastered tasks rechecked after changes.

Never ingest evaluation answers into the training set. Deduplicate semantically as well as by hash, detect contamination, and retain split lineage.

## Catalog generation

Run:

```bash
python tools/build_dreamco_training_catalog.py
```

The script reads the repository's current manifests and writes `data/dreamco_training/catalog.json`. It does not download external data, read course websites, launch model jobs, or alter source datasets. Run it in CI and fail if required manifests are missing or malformed.

## Training readiness

A dataset is not training-ready until:
- ownership/license and intended use are verified per asset;
- provenance and source version are recorded;
- schema, deduplication, privacy, safety, and quality checks pass;
- train/validation/test leakage checks pass;
- the training objective and target model compatibility are documented;
- a human approves any ambiguous/high-impact data use;
- the evaluation plan includes untouched holdouts and regressions.

## Current truth boundary

This directory establishes the canonical index and original DreamCo data format. It does not claim all repository resources have been downloaded or combined into one model dataset. The O*NET synthesis package is a small 44-occupation sample with its own field-level CC BY 4.0 attribution and a private-use license gate; it is not approved for sale. Third-party dataset links in the existing website catalog remain pointers until individually reviewed and ingested.
