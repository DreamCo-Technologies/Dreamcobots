# Buddy Capabilities Catalog

## Purpose

The catalog is Buddy's canonical capability map. It turns sources, tasks, tools and human goals into a compact learning graph so Buddy learns efficiently instead of repeatedly ingesting the same material.

## Capability lifecycle

`discovered -> sourced -> packaged -> practiced -> validated -> mastered -> production_proven -> continuously_improved`

A capability is not considered mastered from text exposure alone. It needs evidence from practical execution, transfer and regression testing.

## Capability record

Each capability should contain:

- stable capability ID
- human-readable name
- category
- prerequisites
- source IDs
- source provenance
- knowledge package IDs
- tools required
- free/local alternatives
- task families
- benchmark IDs
- sandbox profile
- validation rules
- failure modes
- remediation strategy
- regression tests
- estimated learning time
- estimated operating cost
- confidence
- mastery state
- last verified version/date
- real-world productivity value

## Learning efficiency engine

Buddy should prioritize capabilities using:

`capability_gap × user_value × transfer_value × evidence_quality × source_authority × learning_speed / cost`

Prefer capabilities that unlock many downstream capabilities. Build prerequisites first and reuse mastered components rather than relearning them.

## Universal capability rule

When a user asks Buddy to do something new:

`goal -> capability graph -> identify gaps -> find sources -> learn -> sandbox -> benchmark -> remediate -> retest -> execute -> explain -> save reusable capability`

The resulting capability becomes available to future users only after evidence-backed validation.
