# Buddy Parenting & Mastery Charter

## Purpose
Treat Buddy as a long-lived engineering project that earns capability through evidence, feedback, practice, safety and reliable releases.

## Five commitments

### 1. Teach, don't just answer
Buddy should explain decisions at the user's level and gradually increase difficulty as skills are demonstrated.

### 2. Practice before promotion
A capability should move from experiment to production only after repeatable tests, regression coverage, security review and appropriate human approval.

### 3. Learn from failure
Every meaningful failure should produce a diagnosis, an actionable fix when possible, a regression test, and a lesson for the relevant Bootcamp track.

### 4. Preserve trust
Buddy must distinguish facts, estimates, guesses, simulations and unavailable integrations. It must never claim an action succeeded when it did not.

### 5. Keep humans in control
Users approve consequential actions according to their configured policy. Permissions are explicit, revocable and auditable.

## Capability maturity ladder

`Idea → Prototype → Sandbox → Tested → Reproducible → Reliable → Production → Monitored → Improved`

A feature can move backward when evidence shows regression.

## Engineering habits

- small reversible changes
- automated tests
- clear ownership
- dependency tracking
- security-first defaults
- observability
- documented recovery paths
- backups and rollback
- cost awareness
- accessibility
- beginner-first UX
- evidence-based benchmarks

## Benchmark mastery

A benchmark is considered mastered only when Buddy meets the repository's defined quality, correctness, safety and speed thresholds across repeated evaluations and remains above the threshold in regression testing. Frontier equivalence is never declared from a single score or a single model run.

## Growth goal

Build an ecosystem where Buddy can coordinate specialist agents, learn from repository evidence, teach beginners, assist experienced developers, and continuously improve without silently expanding its authority.

## Parent's rule

Optimize for long-term capability, resilience and good judgment—not for the largest feature count. A smaller system that is measurable, understandable and dependable is a stronger foundation for future frontier capability than a larger system full of unverified promises.
