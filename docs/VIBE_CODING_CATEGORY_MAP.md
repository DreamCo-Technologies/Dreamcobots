## Buddy Cross-Combine: Vibe-to-Company Engine

Buddy should treat the map as composable capabilities rather than isolated prompts. A request such as **"make me a game"** can become a coordinated graph of game + website + mobile app + AI NPC system + multiplayer backend + trailer + social clips + ads + community + merchandise + marketplace + analytics + support + updates + monetization.

### Game company blueprint
`game → website → mobile companion → AI NPCs → multiplayer → trailer → TikTok/Reels → YouTube → ads → Discord/community → merchandise → marketplace → analytics → support → update system`

### Hardware startup blueprint
`idea → requirements → architecture → schematic → PCB → firmware → simulation → BOM → manufacturing files → prototype → test plan → mobile app → cloud backend → website → packaging → manual → commercial → ads → e-commerce`

### Movie studio blueprint
`idea → story → screenplay → characters → storyboard → concept art → sets → animation/VFX → soundtrack → trailer → poster → website → social campaign → ads → streaming interface → merchandise`

### Education company blueprint
`course idea → curriculum → lessons → videos → interactive textbook → AI tutor → games → quizzes → student dashboard → teacher dashboard → assessments → certificates → mobile app → website → marketing → subscription`

## Ultimate Buddy capability tree

**CREATE:** Software, Websites, Apps, Games, AI, Hardware, Robotics, Media, Video, Movies, Music, Writing, Design, Education, Business, Science, Engineering, Simulation, VR/AR, Physical Products.

**OPERATE:** Deploy, Host, Monitor, Test, Debug, Maintain, Scale, Secure, Analyze, Automate.

**LEARN:** Research, Experiment, Benchmark, Simulate, Evaluate, Compare, Improve, Remember, Reuse, Generalize.

**SHIP:** Package, Publish, Deploy, Manufacture, Market, Advertise, Sell, Support, Update.

## Evidence contract

Buddy must not equate "generated" with "working." Every capability should progress through:

`IDEA → GENERATED → EXECUTED → TESTED → VERIFIED → DEPLOYED → REAL-WORLD VALIDATED`

Each stage should retain evidence, provenance, test results, benchmark results, dependencies, risks, rollback information, and approval state where applicable. Production readiness must be earned by evidence rather than inferred from the existence of source code.
