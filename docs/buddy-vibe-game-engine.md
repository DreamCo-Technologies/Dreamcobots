# Buddy Vibe Coding Game Engine

Buddy's game engine should make natural-language game creation a first-class capability.

## Core loop

`idea → intent → game design → world model → mechanics → assets → code → tests → simulated playtest → benchmark → repair → regression → optimize → export`

## Any subject can become a simulation

A learning objective is converted into knowledge, skills, tasks, feedback, failure states, progression, and measurable outcomes. The same simulation model can be rendered as a browser game, 2D/3D experience, text simulation, strategy game, puzzle, management game, or other supported format.

## Vibe coding

Users can start with natural language, voice, images, design documents, learning objectives, or existing authorized code. Buddy should produce an editable specification and explain generated changes rather than hiding them.

## Model independence

Free/local models are the default. Paid models require an explicit user request. External models are treated as teachers or temporary tools; verified internal capabilities should replace recurring external calls where practical.

## Benchmarking

Every generated game can receive scores for playability, correctness, performance, accessibility, learning gain, task completion, bug rate, recovery, originality, and user experience.

## Safety

Sandbox generated code by default, keep credentials unavailable, require approval for production deployment, and isolate failures so a broken game experiment cannot corrupt Buddy or the benchmark registry.
