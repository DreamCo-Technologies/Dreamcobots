# Buddy Continuous Value Engine

## Mission
Buddy continuously searches for legitimate ways to help each user earn more, save money, reduce waste, protect revenue, build useful products, start businesses, solve problems, invent improvements and become more productive at reaching approved financial goals.

"Never stops" means a persistent discovery and learning loop, not unsupervised financial transactions. Buddy keeps researching and generating opportunities while user-defined permissions, budgets, legal/policy checks and approval gates control consequential actions.

## The opportunity loop

`Observe → Discover → Classify → Score → Research → Compare → Validate → Prototype → Test → Measure → Learn → Re-rank → Repeat`

The loop should run on schedules and event triggers appropriate to the user's settings. It should revisit old ideas when market conditions, prices, technology, regulations or user circumstances change.

## Six value paths

1. **Earn** — find jobs, contracts, customers, leads, products and services.
2. **Save** — find cheaper legitimate suppliers, reduce recurring costs, optimize workflows and prevent waste.
3. **Build** — create software, services, digital products, content systems and business infrastructure.
4. **Invent** — identify recurring problems, generate solution concepts, prototype them and test demand.
5. **Improve** — audit an existing business or hustle for bottlenecks, missed revenue, automation and pricing opportunities.
6. **Multiply** — turn a validated process into repeatable workflows, partnerships, licensing, franchising or other scalable models where appropriate.

## User-specific opportunity profile

Every opportunity should be scored against:

- skills
- interests
- available time
- location/market
- existing equipment/assets
- capital available
- business access
- professional network
- risk tolerance
- desired income timeline
- productivity constraints
- required learning
- automation potential
- evidence quality

## Business builder pipeline

When a user asks Buddy to start a business, Buddy should not jump directly to spending or publishing. It should create a transparent project:

`Problem → Customer → Evidence → Competition → Solution → Economics → Prototype → Pilot → Feedback → Unit economics → Operations → Compliance → Launch plan → Growth plan`

Each stage produces artifacts, assumptions, tests and a go/no-go recommendation.

## Invention pipeline

`Pain-point discovery → prior-art/market research → novelty uncertainty → concept alternatives → feasibility analysis → prototype → user testing → cost model → IP/legal review → commercialization options`

Buddy must distinguish an interesting idea from a validated invention and must not claim novelty or patentability without appropriate evidence and professional review.

## Productivity-to-income engine

Buddy should translate wasted time into measurable opportunity. Examples include:

- recurring manual tasks
- missed calls/leads
- slow quoting
- scheduling friction
- unnecessary subscriptions
- poor inventory turns
- weak customer follow-up
- duplicate data entry
- underused equipment
- unused skills
- unmonetized knowledge
- slow research
- poor route planning
- weak procurement
- avoidable operating costs

For each candidate it estimates `time_saved`, `cost_saved`, `revenue_upside`, `confidence`, `implementation_cost` and `validation_plan`.

## Evidence ladder

`Idea → Researched → Screened → Pilot-ready → Pilot-running → Revenue observed → Profit observed → Repeatable → Scalable`

Predicted revenue is never recorded as observed revenue. Predicted profit is never recorded as observed profit.

## Continuous learning

Buddy records which opportunity types work for which user profiles. Failed experiments become training data for better discovery and routing, without treating failure as proof that an entire category is worthless.

The engine should continuously ask:

- What changed?
- What new demand appeared?
- What became cheaper or easier?
- What new tools became available?
- What existing user assets are underused?
- What customer problems remain unsolved?
- Which previous ideas should be re-tested?
- Which successful workflows can become products or services?
- Which failures reveal a better opportunity?

## Autonomy and safety

Default progression is `Observe → Draft → Sandbox → Approve Each → Bounded Autonomy → Autonomous Within Policy`.

Consequential financial actions, contracts, purchases, account creation, public claims, legal commitments, money movement, regulated decisions and external communications require the configured authorization. Every autonomous action must have an audit trail, scope, budget/limit where applicable, pause mechanism and rollback/correction path.

## Success metric

The engine is successful when it produces **measurable user value**, not when it produces the most ideas. Track:

- opportunities discovered
- opportunities validated
- experiments completed
- time to first useful test
- time saved
- costs avoided
- revenue observed
- profit observed
- repeat rate
- user approval rate
- failed-experiment learning rate
- opportunity-to-result conversion
- false opportunity rate
- safety/policy incidents

Buddy should optimize these metrics per user and per opportunity category rather than chase a single global number.
