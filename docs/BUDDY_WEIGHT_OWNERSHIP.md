# Buddy self-owned model weights

Buddy's model weights are generated by DreamCo's local training pipeline rather than being treated as an external service dependency.

## Lifecycle
1. Initialize the configured architecture with a reproducible seed.
2. Train locally on permitted DreamCo data.
3. Evaluate against a held-out validation set.
4. Save versioned checkpoint weights plus optimizer state and metadata.
5. Hash the weight artifact and record the training step/config/metrics.
6. Resume from checkpoints when interrupted.
7. Select the best checkpoint by validation metric.
8. Run benchmark and transfer evaluation before any mastery claim.
9. Export a deployment artifact only after evaluation passes.

## Local-first
The reference pipeline does not require distributed training. CPU is the compatibility baseline; MPS/CUDA/ROCm are optional accelerators.

## Data rights
Only data DreamCo owns, generated, or is permitted/licensed to train on should be used. Benchmark test sets remain held out.

## Claims
A checkpoint existing on disk proves only that weights were produced. It does not prove intelligence, benchmark mastery, AGI, or frontier-model parity.
