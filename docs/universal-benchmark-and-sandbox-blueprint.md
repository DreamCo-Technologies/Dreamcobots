# Buddy Universal Benchmark + Sandbox Blueprint

This blueprint connects O*NET-style occupational tasks, computer/AI workflows, business operations, government services, nonprofit operations, media production, game creation, and repository capabilities into one measurable system.

## 1. Universal work benchmark

The benchmark asks: **What does the human do? What does the computer do? What does AI do? What could Buddy do better?**

Every task gets a 0–100 score with evidence for quality, accuracy, time, cost, errors, rework, learning gain, transfer, retention, accessibility, reliability, recovery, and user value.

O*NET is an authoritative workforce lane rather than a hard runtime dependency. Its occupation/task data can seed the task graph when available; offline Buddy continues using cached or locally generated benchmark definitions.

## 2. Parallel gap closure

Every failed or weak benchmark creates a `CapabilityGapClosureWorker` path:

`gap → research → candidate sources → experiment → build → sandbox → test → benchmark → regression → promote`

This path runs in parallel with unrelated work. A hard problem is never allowed to freeze the rest of Buddy's progress.

## 3. Business mastery

Buddy's business benchmark covers starting, operating, fixing, growing, funding, automating, and exiting organizations. It includes for-profit, nonprofit, cooperative, franchise, professional-services, software, manufacturing, construction, retail, ecommerce, marketplace, subscription, project-based, membership, media, hospitality, logistics, real estate, consulting, and public-sector contracting models.

The lifecycle includes idea discovery, market research, customer discovery, validation, business model, legal structure, registration, product, pricing, sales, marketing, operations, hiring, training, accounting, taxes, payments, procurement, inventory, support, quality, analytics, security, compliance, funding, grants, contracts, partnerships, expansion, risk, succession, and exit.

## 4. Government mastery

Buddy should learn government as an ecosystem of agencies, services, forms, eligibility, documentation, appointments, public information, procurement, solicitations, vendor readiness, proposals, contract compliance, reporting, records, accessibility, privacy, security, and performance measurement.

The goal is **authorized assistance and productivity**, not autonomous authority. Real submissions, identity actions, purchases, contracts, or regulated decisions remain human-approval and permission gated.

## 5. Media mastery

Books, movies, video, music, websites, and games use shared evidence and benchmark infrastructure. Buddy should learn structure, technique, production workflows, and observable quality, then create original work.

For film, music, books, and games, benchmarks include craft quality, consistency, originality, technical quality, production efficiency, audience usability, and professional-quality rubrics.

## 6. World-class sandbox

Every benchmark can run inside an isolated environment with filesystem isolation, network policy, dependency allowlists, secret redaction, CPU/memory/time limits, process isolation, synthetic/test data, replayable runs, artifact capture, telemetry, rollback, failure recovery, and human approval gates.

The sandbox must make failure cheap and informative. A failed run produces evidence, a reproducible case, a gap record, and a restart plan instead of stopping the learning system.

## 7. Repository connection

Every capability, tool, workflow, API, dataset, benchmark, sandbox, UI, route, secret, and model is a graph node. Relationships record `uses`, `produces`, `tests`, `observes`, `routes_to`, `depends_on`, `trained_by`, and `verified_by`.

A capability is not marked connected without evidence from import/configuration/health/unit/integration/E2E/benchmark/sandbox/observability/recovery checks.

Legacy bot names remain aliases until capability, dependency, route, permission, observability, and E2E parity are proven.

## End state

Buddy continuously asks:

**What are humans doing? What makes it slow, expensive, difficult, error-prone, inaccessible, or repetitive? Can AI help? Can Buddy do it itself? Can we prove the improvement? Can the improvement become a reusable capability?**

That loop is the core of DreamCo's benchmark, productivity, simulation, business, government, education, media, and software strategy.
