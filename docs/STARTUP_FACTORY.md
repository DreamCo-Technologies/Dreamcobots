# Buddy Startup Factory

Buddy can treat a startup as a staged project rather than a single code-generation request.

## Entry points

A user can start from an idea, sketch, prototype, existing codebase, hardware prototype, existing product, or existing business.

## Build path

`DISCOVER → DEFINE → PROTOTYPE → VALIDATE → BUILD → LAUNCH → OPERATE → SCALE → FUND`

At every stage Buddy should show the current objective, deliverables, dependencies, blockers, cost assumptions, approvals, evidence, and next action.

## What Buddy produces

- Startup profile and category map
- Customer/problem definition and competitive landscape
- PRD or product/service specification
- Architecture, prototype, or build plan
- Validation experiments and acceptance tests
- Business model, pricing hypotheses, and unit economics
- Budget and financial projection with assumptions labeled
- Website/app/product/operations stack plan
- Go-to-market, sales, support, analytics, and KPI plan
- Risk register, security/privacy considerations, rollback plan
- Pitch-deck outline, executive summary, and business-plan outline
- Funding-readiness workspace and financing comparison
- Loan-readiness checklist
- Launch and post-launch learning loop

## Startup coverage

The factory is designed for software/SaaS, AI agents, voice/audio, creator businesses, e-commerce, local businesses, professional services, hardware/electronics, robotics, manufacturing, automotive, education, media/film, games, health technology, fintech interfaces, real-estate technology, logistics, industrial automation, climate/environment, scientific products, developer tools, marketplaces, subscriptions, and hybrid companies.

The 50-category vibe-coding taxonomy remains the canonical cross-category capability map. Startup plans should reuse it instead of creating a disconnected category system.

## Financing and loans

Buddy should compare bootstrapping, customer-funded launches, grants, loans, lines of credit, equipment financing, crowdfunding, accelerators, angels, venture capital, strategic partners, and revenue-based financing when relevant.

For loans, Buddy is an educational decision-support system. It should identify eligibility factors, documentation, current lender/program sources, APR or effective cost, fees, repayment terms, collateral or guarantees, risks, and alternatives. Current offers and eligibility must be sourced at runtime and dated. Buddy must never guarantee approval, invent eligibility, present an estimate as an offer, or hide costs and risks.

Regulated financial, legal, or tax decisions and application submissions require human review.

## Evidence gates

`IDEA → GENERATED → EXECUTED → TESTED → VERIFIED → DEPLOYED → REAL-WORLD VALIDATED`

Source code alone is never sufficient evidence that a business or product is production-ready. The dashboard should make this visible to users.
