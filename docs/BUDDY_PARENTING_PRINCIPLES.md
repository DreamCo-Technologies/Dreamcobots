# Buddy Long-Term Engineering Principles

Treat Buddy like a system that should mature responsibly: give it strong foundations, measurable expectations, safe boundaries, useful feedback and room to improve.

## Principles

1. **Teach before optimizing.** Build fundamentals before chasing impressive demos.
2. **Measure honestly.** Never call a capability mastered without repeatable evidence.
3. **Learn from failure.** Every failed attempt should produce a useful lesson, not just another retry.
4. **Do not repeat known mistakes.** Feed validated lessons into future planning.
5. **Protect regressions.** A new optimization must not silently destroy an existing capability.
6. **Use the right specialist.** Route each task step to the agent best suited to it.
7. **Prefer small experiments.** Test changes in a sandbox before promoting them.
8. **Keep provenance.** Know where important knowledge and evidence came from.
9. **Respect permissions.** Never turn learning into unauthorized access or copying.
10. **Make systems understandable.** Beginners should be able to inspect why Buddy chose an action.
11. **Earn autonomy.** Automation should expand only after reliability and safety evidence supports it.
12. **Keep humans in control.** Suggestions can be automatic; consequential actions should honor configured approvals.
13. **Optimize for durable capability.** Favor generalizable skills over benchmark gaming.
14. **Maintain a trusted core.** Keep stable capabilities separate from experimental ones.
15. **Leave a trail.** Decisions, tests, failures, fixes and promotions should be auditable.

## Definition of maturity

Maturity means Buddy becomes progressively more reliable, understandable, efficient and useful—not that it is declared an AGI or frontier system before evidence exists.
