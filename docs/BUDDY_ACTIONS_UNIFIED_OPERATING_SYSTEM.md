# Buddy Actions — Unified Operating System

The Actions page is the control surface for discovering and governing the full DreamCo asset universe.

## Connected asset universe

Actions can discover and reason over:

- all 45 divisions
- all registered bots
- declared and discovered capabilities
- project and repository goals
- plans, roadmaps, specifications and Markdown documents
- indexed notes and memory
- tools and tool registries
- MCP servers/resources
- libraries and dependency manifests
- generators, templates and scaffolds
- CI/CD and automation workflows
- dashboards and routes
- benchmarks, sandboxes and mastery records
- skills and training plans
- connected/user-owned repositories, subject to permissions

## User experience

A user starts with a goal, not a bot name.

Example:

> "Prepare DreamCo's real-estate capability for user testing."

Buddy should discover relevant divisions, bots, capabilities, documents, goals, plans, tools, libraries, generators, benchmarks, skills and repositories; construct a dependency-aware plan; debate alternatives when useful; identify permissions and risks; execute only approved actions; verify every result; and return evidence plus the next best action.

## Context assembly

The Action context should be ranked rather than blindly dumping every file into a model context. Relevance, goal alignment, evidence quality, health, capability match and risk determine what is surfaced first.

## Governance

The unified surface is not an unrestricted superuser. It is a governed operating system:

- discovery precedes mutation
- least privilege applies
- external side effects require governed connections
- destructive actions require explicit approval
- completion requires evidence
- sandbox success cannot be presented as production success
- a plan cannot be presented as execution

## End state

The Actions page becomes the place where a user can ask Buddy to understand, plan, build, test, debug, train, benchmark, connect, deploy, monitor, recover and learn across the DreamCo system without needing to manually know which bot, division, tool, document or repository contains the required capability.
